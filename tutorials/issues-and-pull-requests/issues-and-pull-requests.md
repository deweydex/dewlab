# Issues and pull requests

What does a repository hold, apart from its files? It also keeps a
record of every problem that anyone has reported, and every change that
anyone has proposed. Both are worth reading, because they are how we fix
this course when something is wrong. On this page we:

- look inside this course's own repository
- see what an *issue* is
- open a real *pull request* and find its parts

## What a repository holds

On the last page we met the idea of a repository. This course has one
too. Can you open
[github.com/deweydex/dewlab](https://github.com/deweydex/dewlab)? You
are now looking at the repository behind this course. Here are three
things in it:

| What | What it is |
|---|---|
| `tutorials/` | A folder with every page you are reading |
| `build.py` | The program that turns those pages into this website |
| `README.md` | The file GitHub shows first, under the list of files |

Nothing here is hidden from you.

## An issue is a report, filed in the open

An *issue* is one report in a repository. It has a title, a
description, and a space where anyone can reply.

How does an issue start? Most pages on this site end with the line
"Something wrong on this page? Tell us." Two of the choices under it
open a new issue in this repository:

- "It gives an error"
- "The page is wrong, or I could not follow it"

GitHub opens the new issue with the page and its version already filled
in.

[The open issues](https://github.com/deweydex/dewlab/issues) are public,
like everything else in this repository. Anyone can read them, with no
account at all. To open a new issue, you sign in to your GitHub account.
You do not need permission from anyone for either.

## A pull request is a proposed change

A *pull request* is a set of edits that someone sends to a repository,
so that another person can review them.
[Pull request #151](https://github.com/deweydex/dewlab/pull/151) is a
real one. It added the "Something wrong on this page? Tell us." line
from the section above. It also added a way to switch that line off
quickly.

1. Open pull request #151.
2. Can you find the exact lines that changed?
3. Can you find the conversation about those changes?
4. How did it end? Look for the decision at the end.

Every pull request has these three parts:

- the exact lines that changed
- a conversation about them
- a decision at the end: accept the change, or ask for something
  different first

## What we have now

We can now read the two records a repository keeps, beside its files.

| Word | Meaning | Example |
|---|---|---|
| *issue* | One report in a repository, with a title, a description and replies | a report that a page gives an error |
| *pull request* | A set of edits sent to a repository for someone to review | pull request #151 |
