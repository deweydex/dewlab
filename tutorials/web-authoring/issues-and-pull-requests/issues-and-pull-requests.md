# Issues and pull requests

A repository is more than the files sitting in it. It also holds a record
of every problem anyone has reported and every change anyone has
proposed. Both are worth reading, because they are how we fix this course
when something is wrong.

## What a repository actually holds

Open [github.com/deweydex/dewlab](https://github.com/deweydex/dewlab)
and you are looking at this course's own repository, the kind of thing
your account page described. `tutorials/` holds every page you are
reading, `build.py` is the script that turns them into the site, and
`README.md` is the file GitHub shows first. Nothing here is hidden from
you.

## An issue is a report, filed in the open

Most pages on this site end with a line: "Something wrong on this page?
Tell us." Choose "It gives an error" or "The page is wrong, or I could
not follow it." GitHub opens a new issue in this repository, with the
page and its version already filled in. An *issue* is just that: one
report, with a title, a description, and a place for anyone to reply.
Opening one does not need permission from anyone. Reading one does not
either — [the open issues](https://github.com/deweydex/dewlab/issues)
are public, same as everything else here.

## A pull request is a proposed change

A *pull request* is a set of edits, sent to the repository for somebody
to review. [Pull request #151](https://github.com/deweydex/dewlab/pull/151)
is a real one: it added the "Something wrong on this page? Tell us."
line described above, along with a way to switch it off in a hurry.
Let's open it and see what a pull request looks like. It shows three
things: the exact lines that changed, a conversation about them, and a
decision at the end — accept the change, or ask for something different
first.
