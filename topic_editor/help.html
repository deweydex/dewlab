The topic editor

A page for drawing the map of what a student needs before what. This is how it works.

The map is a graph. Each box is a topic, and a link between two boxes says how they relate. The editor lets you draw those links by hand, move topics around, and send the result back into the repository.

Getting around

Drag empty space to move around. Hold Ctrl and scroll to zoom. Fit shows the whole field. Type in the search box to find a topic; / puts the cursor there.

Drag a topic to move it. A topic you have dragged stays where you put it, and shows a darker border. Let go releases them all, so the links can arrange them again.

Linking two topics

Tap one topic, then another. A link appears from the first to the second. It starts as requires, meaning the first has to come before the second.

Tap the second topic again to change what kind of link it is. Each tap moves to the next kind in the list below, and a tap after the last one removes the link. Pressing 1 to 5 chooses a kind directly.

KeyKindWhat it says
1requiresYou cannot do the second without the first. Only this kind decides the order.
2helpsThe first makes the second easier, but is not needed.
3applied inThe first is a tool the second uses.
4interdependentThe two need each other. This link has no direction.
5involvesThe two touch each other, more loosely. No direction.

A requires link that would make a loop is refused, and the loop is named. The editor makes it a helps link instead, so nothing is lost.

With a topic chosen, picking a search result links to it. That is the way to reach a topic that is off the screen. Hold Shift to go to the result without linking.

The small numbers on a box are its links: in on the left, out on the right. At nine either way the editor warns you, because that is about the most a student can hold.

The panel

Choose a topic and the panel on the right shows everything it has: what comes before it, what it comes before, and what goes both ways. Each link has a menu to change its kind, a ⇄ to turn a one-way link round, and a × to remove it. Tap a name in the list to go to that topic.

The topic's name, column, tags and description can be changed here too. Choose New column… in the column list to make one.

Three bigger changes

ButtonWhat it does
Cut everything beforeRemoves every one-way link into this topic, so nothing comes before it.
Merge another into this…Tap a second topic. It is folded into this one: its outcomes, uses and links come across, and it is gone.
Split this…Makes two topics out of one. Both halves keep every link, so remove what does not belong to each afterwards.

Building out from a topic

Choose a topic and press Build out from here. It goes to the centre. Every topic that has no links yet waits in rings around it, grouped by column. One tap on a ring topic links it to the centre and brings it in. The rings are always what is still unplaced, so they empty as you go.

To keep going outward, choose a linked topic and press the same button. It becomes the new centre.

How the field moves

Nothing here assumes an order. Topics push each other apart, a link pulls its two ends together, and a one-way link leans its far end a little lower than its near end. So an order appears as you draw it, without a row ever being imposed. Flow down switches that lean off.

Columns and filters

Each topic belongs to a column, which is its colour. The chips under the search box dim every column but the ones chosen, which makes the field easier to read while you work on one subject. They do not change anything.

Saving

Everything you do is saved in this browser as you go, and Ctrl+Z undoes any of it. The note by the search box says how many changes have not yet been exported.

ButtonWhat it does
ExportSaves your work as a file called topic-graph-edits.json.
ImportLoads a file you exported before.
Bring in repo linksAdds every link the repository's graph has, keeping yours.
Start againThrows away every change. It asks whether to start from the repository's graph or from the topics alone.

Getting it into the repository

The editor never writes to the repository itself. Export a file, then in a checkout run:

python3 dev/apply_topic_edits.py topic-graph-edits.json

That writes your graph into planning/curriculum/topics.yaml and strands.yaml. From then on the graph is what those files say, and the pair judgements and decisions under review/ are the record of how it got there.
